# Plan: an accessible ACID Method skill

## 1. Preserve the framework — prepared

Keep unchanged copies of the three diagrams and a readable text reference. Preserve Abstraction, Creativity, Intention, Depth, their domains and elemental metaphors, and the diagram's relational framing. Identify implementation additions explicitly.

## 2. Make it usable — prepared

Provide one portable `acid-method` skill, optional Codex interface metadata, a self-contained prompt for other LLMs, host-specific installation steps, and a preference for default analysis. Include worked examples and CC BY 4.0 attribution terms selected by the method owner.

## 3. Check the first draft — package checks complete

Validate skill structure, reference links, portable-prompt parity, and ZIP contents. Review realistic examples for useful differences between the lenses. Publish version 0.1.0 as an initial implementation with honest testing limits.

## 4. Validate behaviour and refine — next

Run the evaluation cases in fresh Codex and Claude Code sessions and in one prompt-only LLM. Test implicit activation separately from explicit invocation. Review the methodology with the owner, correct demonstrated problems, and record results before claiming verified compatibility.

## 5. Grow from demonstrated needs — later

Add domain-specific examples, translations, or host packaging when actual users need them. Add scoring only if the owner chooses a defined rubric, and distinguish it from the original diagrams. Keep the core method and portable prompt aligned.
